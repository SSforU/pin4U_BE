# ADR-0003: 배포 파이프라인 게이트

## 상태
채택 (2026-08-23)

## 맥락
`deploy.yml`이 `on: push: branches: [main]`으로 설정되어 main 머지마다 EC2 배포가 트리거된다.
P0~A-FIX 동안 20회의 배포 시도가 전부 failure로 끝났다 (AWS 자격증명 미설정).
개발 중에는 실배포가 불필요하며, 원치 않는 워크플로 실행은 Actions 비용과 로그 오염을 유발한다.

## 검토한 선택지

### (A) 워크플로 삭제
- 장점: 확실한 차단
- 단점: 배포를 다시 켜려면 파일을 재생성해야 하고, 히스토리에서 설정이 사라짐

### (B) `on: workflow_dispatch` 로 변경 (수동 전용)
- 장점: 단순
- 단점: 자동 배포 경로가 완전히 사라짐. CI/CD를 되살리려면 트리거를 다시 추가해야 함

### (C) 조건부 게이트 (feature flag)
- 장점: 워크플로 코드 유지, 변수 하나로 on/off 전환, 수동 실행도 가능
- 단점: GitHub Variables 설정이 필요하다는 사실을 알아야 함

## 결정
**(C) 조건부 게이트를 채택한다.**

```yaml
if: github.event_name == 'workflow_dispatch' || vars.DEPLOY_ENABLED == 'true'
```

## 근거
1. 워크플로를 삭제하지 않으므로 배포 구성이 코드로 보존된다.
2. `DEPLOY_ENABLED` 변수를 설정하지 않으면 push 트리거가 자동 스킵된다.
3. 배포가 필요할 때: 변수를 `true`로 설정하거나, Actions 탭에서 수동 실행.
4. 워크플로 파일 변경 없이 운영 모드 전환이 가능하다.

## 감수한 트레이드오프
- 신규 팀원이 `DEPLOY_ENABLED` 변수의 존재를 모르면 "왜 배포가 안 되지?"로 혼란 가능.
  → deploy.yml 상단에 주석으로 명시, README에도 기재.
