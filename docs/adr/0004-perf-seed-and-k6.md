# ADR-0004: 성능 시드 데이터 및 k6 부하 테스트 체계

- 상태: 수용
- 일시: 2026-08-30

## 맥락

포트폴리오에 기재할 성능 수치의 근거가 필요하다. 추정치가 아닌 실측값을 확보하려면
재현 가능한 시드 데이터와 부하 테스트 스크립트가 갖춰져야 한다.

## 결정

### 시드 데이터 (`scripts/seed-perf-data.sql`)
- 규모: 사용자 5, 역 10, 요청 50, 장소 500, 집계 500건
- 모든 INSERT에 `ON CONFLICT` 절을 사용해 멱등성 보장
- Docker Compose의 `/scripts` 볼륨 마운트로 컨테이너 내부에서 직접 실행

### k6 시나리오 3종
| 시나리오 | 목적 | 부하 |
|----------|------|------|
| theme1-query | 조회 API 응답시간 | 10 RPS × 30s |
| theme2-async | 비동기 추천 쓰기 | 5 RPS × 30s |
| theme3-concurrency | 동시 쓰기 경합 | 50 VU × 1 iter |

- HMAC 토큰을 k6 내부에서 `crypto.hmac('sha256', ...)` 로 생성하여 인증 통과
- `handleSummary`로 `docs/perf/k6/*.json`에 결과 자동 저장
- 임계값(thresholds)을 스크립트에 내장해 pass/fail 자동 판정

### 인증 전략
서버의 HMAC 쿠키 인증을 그대로 사용한다. 테스트 전용 인증 우회 없이
k6에서 동일한 알고리즘으로 토큰을 생성하므로 실제 운영과 동일한 경로를 측정한다.

## 결과

- 3개 시나리오 모두 checks 100%, 에러율 0% 달성
- 조회 p95 19.73ms, 비동기 쓰기 p95 34.48ms, 동시성 p95 66.23ms
- 측정 결과 JSON이 git에 커밋되어 포트폴리오 근거로 사용 가능

## 대안 검토

- **Gatling/JMeter**: JVM 기반으로 리소스 소비가 크고 스크립트가 장황함. k6는 JS 기반으로 간결하고 CI 통합이 용이
- **테스트 전용 인증 우회**: 실제 경로를 측정하지 못하므로 기각
